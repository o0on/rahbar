# AI usage

Every entry names the tool, what it actually produced, and what we did to it afterwards. Using AI here is not a penalty; shipping its output untested would be.

| Tool | What it wrote or shaped | What we changed afterwards, and why |
| --- | --- | --- |
| OpenCode (CLI coding agent, model `mimo-v2.6-flash-free`) | First drafts of the five indexer stages (`extract`, `clean`, `chunk`, `embed`, `store`), the API services (retriever, cache, grounding, answer orchestration), the four scoring functions in `eval/run_eval.py`, and the unit tests | Every draft was run against a live stack before commit. Real runs found three bugs the model did not anticipate: pdfplumber's `extract_text()` interleaves multi-column table cells (fixed by cropping table regions and rendering Markdown rows), header/footer stripping was eating the first and last lines of short pages (fixed by sampling margins only on pages with 6+ lines), and Chroma rejects any `collection.modify()` that mentions `hnsw:space` even when unchanged (fixed by stripping the key, with a fake that now rejects it too). The test suite (103 tests) is what keeps these fixed |
| OpenCode (same agent) | Drafts of the documentation: corpus map, pipeline notes, failure-analysis blocks | Facts were re-checked against the documents instead of trusting the model: every golden `expect` value (attendance 100%, CGPA 2.00, Rs 30,000 admission fee, A- = 3.67, both withdrawal deadlines) was read out of the source PDF/HTML by hand before it went into `eval/golden.yaml`, and every `(source, section)` pair was verified against a real pipeline run |
| OpenCode (same agent) | Strategy for the golden set and the chunk-tuning measurement | The golden set was written **before** any tuning (section 5.1) so the measurements could not be fitted to it; the tuning script reuses `run_eval.recall_at_k` and the retriever's own superseded-filter regex instead of reimplementing either, so the number in `docs/PIPELINE.md` is the number the gate uses |
| Local models (Ollama `nomic-embed-text`, `llama3.2:3b`) | These are product components, not development tools: the embedder and generator the system ships with | Parameters are the repo defaults (temperature 0.2, 768-dim embeddings); nothing about them was hand-tuned to make scores look better — the golden gate measures retrieval, not model chatter |

Rules we held ourselves to: no generated code was committed without running `pytest`, `ruff` and `mypy` first; no model output was used as a factual source for the corpus or the golden set (documents were read directly); and this table is updated whenever a new tool is used.
